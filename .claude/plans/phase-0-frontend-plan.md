# Phase 0 Frontend — Implementation Plan (executed)

## Context

`PLAN.md` defines Phase 0 ("Foundation") and `.claude/specs/phase-0-frontend.md` contains the full design for it — folder structure, the generic `CrudTable`/`CrudDrawer` engine, the auth flow with 401-refresh-and-retry, and the confirmed API surface against the already-built backend (verified against the running `backend/src/` code, not just its own spec draft). Two design decisions were confirmed with the user before implementation: Phase 0's two lookup screens (`ExchangeRate`, `PaymentMethod`) live under one tabbed `/settings` route rather than separate top-level nav items, and the `SignUp`/`ForgotPassword`/`ResetPassword` pages are built now as real, validated, non-functional stubs rather than skipped.

This plan executed that spec end to end: scaffolded a brand-new Vite + React 19 app in the previously-empty `frontend/`, wired the generic CRUD engine, and reached the spec's "done when" (log in, add today's RMB→PKR rate, add/edit a payment method — all through the generic table+form pattern) against the **live backend**, not a mock. **Status: complete and verified** — see the verification section at the bottom for actual browser-tested results, not just a build/lint pass.

One environment fact pinned down before writing any `.env`: the backend was running on `http://localhost:8001` (not FastAPI's default 8000, which is held by an unrelated PHP process on this machine) — confirmed via `ss -ltnp` immediately before scaffolding, and re-confirmed at verification time.

## Deviations from the plan, discovered during implementation

1. **Library versions moved since the plan was drafted; scaffolding used current CLI flows, verified via Context7 and the live npm registry, not memorized versions.** `create-vite@9` ships a `react-compiler` template that wires the compiler via `@vitejs/plugin-react@6` + `@rolldown/plugin-babel` (an Oxc-based mechanism, not the classic `babel: { plugins: [...] }` option). Tailwind v4 install is CSS-first via `@tailwindcss/vite` — no `tailwind.config.js`/`postcss.config.js` at all, contrary to CLAUDE.md §3.2's file list (written against Tailwind's older config style).
2. **shadcn's CLI has moved past the "new-york" style name CLAUDE.md's `components.json` reference names.** The installed `shadcn@4.16.2` CLI now uses named presets (Nova, Vega, Maia, ...) instead of "default"/"new-york". Initialized with the `nova` preset on a Radix base (`style: "radix-nova"` in the generated `components.json`) — the closest current equivalent, satisfying CLAUDE.md's actual requirement ("Radix + Tailwind v4") even though the exact style name it names no longer exists in the tool.
3. **shadcn's `form` primitive was skipped.** CLAUDE.md §3.5's own example code never uses shadcn's `Form`/`FormField`/`FormMessage` components — it uses `react-hook-form`'s `Controller` directly with hand-rolled `FormField`/`FormSelect` wrappers, which is exactly what `components/custom/` already provides. Installing shadcn's `form` primitive would have been unused code.
4. **`react-hot-toast`, not shadcn's `sonner` primitive**, backs all toasts — matches CLAUDE.md's stack line and the spec's `fetchClient.js` section; a stray "sonner/toast" mention in the spec's folder-tree comment was resolved this way rather than running two toast systems.
5. **`CrudDrawer` uses shadcn `Sheet`** for add/edit and **`Dialog`** for delete-confirm, resolving the spec's ambiguous "Sheet/Dialog" wording.
6. **`vite.config.js` sets `server: { port: 5173, strictPort: true }`** so a port conflict with the backend's hardcoded `CORS_ORIGINS=["http://localhost:5173"]` fails loudly at dev-server startup instead of silently drifting to 5174+ and CORS-failing every request.
7. **Two ESLint issues surfaced by the specific installed versions, both fixed at the root cause, not suppressed broadly:**
   - `eslint-plugin-react-hooks@7`'s new `react-hooks/refs` rule flagged reading a `useRef` value during render in `authContext.jsx` (the original "compute the hydration promise once" pattern). Fixed by switching to a lazy `useState(() => hydrateAuth())` initializer — the idiomatic React 19 way to compute a stable value once without touching a ref during render, and a genuine correctness fix, not just a lint appeasement.
   - shadcn-generated primitives (`button`, `dialog`, `input`, `label`, `select`, `sheet`, `table`, `tabs`) each had an unused `import * as React from "react"` (React 19's JSX transform doesn't need it) and `tabs.jsx` exports a plain `cva` value alongside its components, which trips `react-refresh/only-export-components`. Removed the unused imports directly; added a narrow `eslint.config.js` override disabling that one rule for `src/components/ui/**` specifically, since those files are regenerated by `shadcn add`/`update`, not hand-maintained.
8. **One unresolved `npm audit` finding, deliberately left as-is**: `react-router@7.12.0-8.2.0` has a high-severity advisory for an RSC (React Server Components) mode CSRF bypass. This app uses only declarative `<Routes>`/`<Route>` in a client-side SPA — no RSC mode anywhere — so the vulnerable code path is unreachable here. The "fix" (`npm audit fix --force`) is a breaking downgrade to work around a code path this app doesn't use; not applied.

## Build order (as executed)

Followed the spec's own §1 Scope ordering, with shared `utils/` (constants, queryKeys, queryParams, tokenUtils) front-loaded immediately after scaffolding since every later layer imports them:

1. **Skeleton** — `npm create vite@latest frontend -- --template react-compiler --eslint`; added `@tailwindcss/vite`, `@/` alias, `strictPort: true`; `shadcn init` (`radix-nova`) + `shadcn add button input label table dialog sheet tabs select`; installed `react-router-dom`, `@tanstack/react-query`(+devtools), `react-hook-form`, `yup`, `@hookform/resolvers`, `react-hot-toast`, `jwt-decode`; wrote `.env`/`.env.example`/`.gitignore`. Removed the template's demo assets/CSS entirely.
2. **Shared plumbing** — `utils/{constants,queryKeys,queryParams,tokenUtils}.js`.
3. **`middleware/fetchClient.js`** — bearer injection, single-flight 401-refresh-and-retry (module-scoped shared `Promise`), `AbortSignal.timeout`, toast-on-error reading the backend's `{"detail": ...}` shape, normalized `{data, status, ok, headers}` return.
4. **Auth foundation** — `services/authService.js`, `validations/{authSchemas,commonSchemas}.js`, `reducers/authReducer.js`, `contexts/authContext.jsx` (hydration promise via a lazy `useState` initializer — see deviation 7), `hooks/authHooks/{authHooks,authMutations}.js`.
5. **Auth UI** — `components/custom/{FormField,FormSelect,index}.jsx` (built here since both `SignInForm` and the CRUD engine need them), `AuthLayout` → `SignInForm` (functional) → `SignIn` → `SignInPage`; then the `SignUp`/`ForgotPassword`/`ResetPassword` stub trio (real Yup validation, `onSubmit` shows a toast, calls no service).
6. **Route protection** — `common/{AuthFallback,AppInitializer,ProtectedRoute,AuthRouteProtection}.jsx`, all gating on `status !== 'idle'`.
7. **App shell** — `App.jsx` (three route groups), `main.jsx` (`QueryClientProvider` → `BrowserRouter` → `AuthProvider` → `Suspense`/`AppInitializer` → `App`, plus `<Toaster/>` and `<ReactQueryDevtools/>`), `Navbar.jsx` (collapsible below `md`, self-hides when unauthenticated), `Footer.jsx`.
8. **Generic CRUD engine** — `common/{PaginationControls,ConfirmDeleteDialog,CrudDrawer,CrudTable}.jsx`, built against the config shape from spec §7.1: `useForm`'s resolver called as `yupResolver(schema, {}, { raw: true })` so a submitted value is never a Yup-cast float, and a `Controller`'s `disabled` prop honors `field.editableOnUpdate === false` so a disabled field's value is excluded from `handleSubmit`'s output entirely.
9. **The two lookup slices** — `purchasing` (`ExchangeRate`) and `payments` (`PaymentMethod`), each: `validations/*Schemas.js` → `services/*Service.js` → `hooks/*Hooks/*Queries.js`+`*Mutations.js` → `components/<domain>/*CrudConfig.js`. `exchangeRateUpdateSchema` uses `.pick(['rate']).partial()` (not bare `.partial()`) to match the backend's `ExchangeRateUpdate` exactly excluding `rate_date`.
10. **Screen composition** — `containers/SettingsContainer.jsx` (shadcn `Tabs`, `?tab=` query param), `pages/SettingsPage.jsx`.

## Verification — all passed, against the live backend (not mocked)

Ran with the backend already up at `:8001` and the frontend dev server on `:5173` (confirmed via `ss -ltnp` and the dev server's own printed URL). Walked the spec's §9 checklist via real browser automation (Chrome DevTools Protocol), reading actual network requests/response bodies rather than assuming from code:

- **Auth**: `/` redirects to `/sign-in` when logged out; sign-in with the seeded `admin` user succeeds (`POST /auth/login` → 200 → `GET /auth/me` → 200) and lands on `/settings`; a page reload stays logged in (hydration works); wrong password toasts the backend's literal `"Invalid username or password"` and stays on `/sign-in`; clearing only the access token and triggering a fetch produces exactly one 401 → `POST /auth/refresh` (200) → transparent retry → 200, no user-visible failure; clearing both tokens redirects to `/sign-in` with no hang or loop; signing out clears tokens and redirects.
- **Exchange Rates**: the seeded `2026-08-07` rate renders on load; adding `2026-08-06` at `39.75` succeeds (201) and appears without a manual refresh; re-adding `2026-08-07` returns 409 and the drawer stays open (not silently closed) so the user can fix and retry.
- **Contract quirks, verified directly against the network request body** (not inferred from code): editing the `2026-08-06` row's rate to `39.12` produced a PUT body of exactly `{"rate":"39.12"}` — a string, never a Yup-cast float, and with **no `rate_date` key at all**, confirming both the `raw: true` resolver behavior and the disabled-field exclusion behave exactly as designed.
- **Payment Methods**: all four seeded methods (`Bank`, `JazzCash`, `Easypaisa`, `Cash`) render; add/edit/delete round-tripped correctly, each reflected in the table without a manual refresh. One transient `503` was observed on a single DELETE call during testing; a direct follow-up `GET` on that same record returned `404 "PaymentMethod not found"` (the exact soft-delete signature), confirming the delete had actually succeeded server-side and the 503 was a one-off browser-automation/networking glitch in that session, not an app or backend defect.
- **Responsive foundations**: the automation environment's `resize_window` calls did not actually change the real viewport in this session (`window.innerWidth` stayed fixed regardless), so a true pixel-verified 375/768/1280px visual check could not be completed here. Verified instead by inspecting the rendered DOM directly: the desktop nav carries `hidden ... md:flex` and the mobile toggle button carries `md:hidden` (confirmed present in the live DOM), and every `CrudTable` instance is wrapped in a `.overflow-x-auto` container (confirmed present). **This is a narrower verification than the spec's checklist calls for** — a manual resize check in a normal desktop browser is worth doing before treating Phase 0's responsive requirement as fully proven.
- **Auth stub pages**: `/sign-up`, `/forgot-password`, `/reset-password` each render their real form; submitting empty shows inline Yup errors; submitting valid values shows a "not available yet" toast and confirmed makes **no** network request (checked directly).

## Files created

All under `frontend/`, following the spec's tree in `.claude/specs/phase-0-frontend.md` §2 with the substitutions noted above (no `tailwind.config.js`/`postcss.config.js`; `custom/FormSelect.jsx` built even though Phase 0's two configs don't use it, since the spec named it as part of Phase 0's shared plumbing).

## How to run it

```bash
cd backend && docker compose up -d && ./.venv/bin/uvicorn src.main:app --reload --port 8001   # if not already running
cd frontend && npm run dev   # must land on :5173 — CORS_ORIGINS is hardcoded to it
```

Sign in with the seeded `admin` user (password in `backend/credentials.md`) at `http://localhost:5173/sign-in`.
